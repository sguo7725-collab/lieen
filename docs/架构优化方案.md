# 碎碎清单 架构优化方案（2026-11-24，1.22.0 之后）

目标：让以后改功能「改一处、只动一处」，并且每次改完都能自动知道有没有改坏。
原则：**不改用户看得到的任何东西**（界面、数据、行为一律不变），每一步都能被测试证明“改前改后一样”。

## 现状（量过的数字）

| 部分 | 现状 | 问题 |
|---|---|---|
| `app/app.js` | 2440 行，一个大函数，18 个功能段共用全局变量 | 找东西难，改一处不知道影响哪里 |
| `app/pro.js` | 1676 行，同样结构，20 个功能段 | 同上 |
| CSS | 6 个文件 4700 行，`!important` 814 个（pro.css 435、settings.css 231） | 后写的规则层层盖前面的，1.22 的穿模就是被一条 `margin:0!important` 吃掉了间距 |
| 测试 | 22 个 `verify-*.cjs`，按版本号命名，没有一键全跑 | 不知道某功能被哪些测试覆盖；`npm run test:all` 只跑其中 4 个 |
| 版本与缓存 | 网页离线缓存版本靠手改字符串；安卓内部版本号原来绑 CI 次数 | 忘改不报错，某天突然出问题（1.22 换仓库后安卓 -25 就是这样） |

## 方案（分四步，按风险从低到高）

### 第 1 步：拆分大文件（不改运行时）
- 源码放到 `src/app/*.js`、`src/pro/*.js`（放在 `app/` 外面，不会被打进安装包），**按功能一段一个文件**（日期、数据校验、清单、添加、编辑、新的一天、备份、分组、回顾、快速输入、提醒、搜索、计时、手感、事件……）。
- `scripts/build-web.cjs` 把它们按顺序拼回 `app/app.js`、`app/pro.js`。手机和网页加载的还是这两个文件，**运行时零变化**。
- 为什么不直接用浏览器模块（import）：现在 18 个功能段共用同一组变量（state、filter……），硬拆成模块要改上千处引用，风险大；而且 iOS 外壳自定义协议对模块脚本的 MIME 有严格要求。先“拼接式拆分”，以后再逐段收紧成真正的模块。
- 验收：第一次拆分后拼回来的文件与原文件**逐字节相同**。

### 第 2 步：自动化版本号与缓存
- `build-web.cjs` 根据网页文件内容自动算出离线缓存版本写进 `sw.js`，不用再手改。
- 安卓内部版本号已改为按时间（1.22 已完成）。
- CI 打包前先跑 `build-web.cjs --check`：源码和拼好的文件对不上就直接失败，防止“改了源码忘了拼”。

### 第 3 步：一键全量测试 + 视觉安全网
- `npm test` 改为一键跑：拼接检查 → 全部 22 组功能测试（逐个串行，避免机器负载导致的动画计时误报）→ 穿模检查。
- `scripts/test-map.md`：每个功能被哪些测试覆盖。
- 新增 `scripts/visual-diff.cjs`：11 个主题 × 主要画面 × 手机/iPad 截图，和基准图逐像素比较。以后整理 CSS 时，只要比较结果是“0 处不同”，就证明界面没变。

### 第 4 步：CSS 整理（分批做，每批都用第 3 步的视觉比较把关）
1. 把 1.22 临时追加在文件末尾的补丁归位到各自组件处。
2. 主题改成“变量”：每个主题只定义颜色、圆角、阴影、字体等变量，组件统一读变量，不再逐个组件覆盖。
3. 逐个去掉不需要的 `!important`，目标先降到 300 个以内。
这一步工作量最大（4700 行 × 11 个主题），要分几个版本逐步做，**每批都必须视觉比较 0 差异才合并**。
